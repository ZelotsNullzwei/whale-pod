这一版把**"花钱的地方"重新量了一遍**，并且**把车牌内页整条路换掉了** —— 原来那条路拿到的根本不是漫画。

导语之外，**请重点看最后一节「注意事项」** —— 里面有几条是这一版**新引入的依赖和限制**，不知道会以为功能坏了。

# 一、车牌内页：**整条路换掉了**（这一版最大的改动）

## 症状：她说看到了，其实什么都没看到

把截出来的 6 屏喂给模型后，它的原话是：

> 「你发的那六屏，在我这儿**全是同一个网页窗口** —— 中间那块**广告霸屏**霸得一点缝都不留，背景只漏出一点点头、一截蓝袖子…」

**自己把那张拼图看了一遍 —— 确实如此**：6 格全是**网站自己的门面**（顶部横幅、「站长官方推荐」、浮层按钮），**漫画只在底下漏出一条**。

**结论**：旧的"开浏览器 + 滚屏截图"这条路，**拿到的是网站 UI，不是漫画** ✗。

## 为什么原来会这样

那个站的阅读器是**浮层式**的：正文图后面盖着常驻的横幅/推荐位，滚屏时**门面不动、漫画在底下滑** —— 截屏当然只能截到门面。

「把广告点掉再截」是**碰运气**：广告位会换、关闭按钮位置会变、有时根本没有。

## 现在怎么做（**换成直下图片**）

在那个站的**阅读器 HTML** 里，图片清单是**明文**的：

```js
var page_arr = ["00001.webp","00002.webp",…]      ← 一次普通 fetch 就有
图片实际地址：https://cdn-msp<N>.<域名>/media/photos/<id>/00001.webp
```

于是：

```
❶ 认到「JM 1234567」或 18comic 链接
❷ fetch 作品页 → 取章节号 → fetch 阅读器页 → 解析 page_arr
❸ 均匀抽 N 页，**直接下图片**（全分辨率、没有广告）
❹ 借浏览器当 canvas，拼成**一张网格图**（省 token；失败才退回多张）
❺ 回复先说"我看看"，后台看完再补一条
```

**实测对比**：

| | 旧路（截屏） | 新路（直下） |
|---|---|---|
| 耗时 | ≈ **27 秒** | ≈ **7 秒** |
| 拿到的东西 | **网站门面 + 广告** ✗ | **干净漫画页，全分辨率** ✓ |

## 拼图：为什么是**网格**不是竖排

一张图的 token 是**固定的**，所以格子要摆成**接近方形**，别拉成条：

```
竖排 6 屏 = 339 × 2736  → 比例 1:8  窄长条 → 被缩得更狠 ✗
网格 3×2  = 1017 × 912  → 比例 1.12:1       → 缩得最少 ✓
```

⚠️ 后来又加了一条：直下的是**全分辨率**页，6 页拼 3×2 会到 **2880×2806 / 810KB** —— 太大，上游会挂死。现在**缩到总宽 ≤1200**，成品约 **1200×1170 / 217KB**。

## 措辞：从"交摘要"改成"给你自己用"

她原来**约一半的情况会顶回来**：

> 「这个我不接…我不给你逐段复述画面内容——**别让我当旁白念**。」
> 「这个我不给你讲…**还要我一段一段给你复盘**？」

**根因在措辞**：原来写的是「★ 要说的是『概况』，照这个格式：前 X 页是…」—— 那是**"当旁白复述"的任务框架**。

改成把"印象"定位成**给她自己用**（并明确免掉"当旁白"），实测：

| | 改前 | 改后 |
|---|---|---|
| 给出分段印象 | 2/4 | **4/4** |
| 收尾顶回去 | 4/4 | **0/4** |

⚠️ 中途踩过一个坑：**加"允许她拒绝"时没写前置条件** —— 她**直接拿它当捷径，印象也不给了**（掉回 2/4）。加上「**先把大概什么调子一句带过去，再拒**」之后两个指标才同时到位。

## 面板：新增「车牌（漫画）」一节

之前 `jmRead` **完全只能改 config.json**。现在面板上能开关、能调抽几页。

⚠️ **配置挂在顶层 `jmRead`，不在 `qq` 里** —— 写面板时差点按 `qq.jmRead` 接，那样会**静默失效**（面板存得下去，后端读的还是默认值，界面上看不出异常）。

# 三、B 站视频：新增**看画面 / 只听**两种模式

**看画面不需要装 ffmpeg** —— B 站自己的 `x/player/videoshot` 接口就返回**分镜图**（10×10 网格）。

- **只听**（默认）：转写 + 评论 + 弹幕 —— 便宜，看不到画面
- **看画面**：把分镜图喂给视觉模型 —— 能聊"画面在发生什么"，**每张图都花钱**

面板上单独一节切换（默认仍是"只听"，保持原来的成本）。

⚠️ 分镜图的**时间字段有秒/毫秒两种**，靠比值 >100 判断。

# 五、车牌识别：现在认**链接**

原来只认 `JM 1234567` 这种写法。你发链接时她会说「我这边打不开，链接是死的」。

现在认三种：

```
18comic.<后缀>/album/<编号>      ← 作品链接
JM 1234567                       ← 简写
禁漫 1234567                     ← 中文写法
```

⚠️ **故意不认"裸数字"** —— 房间号、订单号、股票代码都会被误认成车牌。**只认带标识的**。

# ★ 注意事项（这一版新引入的依赖和限制）

## 1. 车牌内页**仍然要本机装 Edge 或 Chrome**

直下图片这一步不需要浏览器，但**拼图那一步借浏览器当 canvas 用**（WhalePod 是零依赖的，没有 sharp）。

缺浏览器时整条路降级 —— **不会静默失败**：日志和注记都会说"打不开"，面板「环境依赖」那节也会**照实显示**。

## 2. **「看画面」是唯一真花钱的开关**

每张分镜图都进视觉模型。默认是**只听**，想要画面才切。

- B 站分镜图：**一张 10×10 网格**
- 车牌内页：**抽几页拼成一张网格**（一张图的 token 是固定的）

## 3. 直下依赖**站点结构**（`page_arr`）

那个站改版（字段改名、改成接口返回）时，直下会失败 —— 这时**自动退回**旧的截屏那条路（就是上面说的"只能截到门面"那条）。

**最坏情况 = 加这个功能之前的行为**，不会更糟，但**也拿不到干净图**。

## 4. `scramble_id`：大编号作品的图**可能被打乱** ⚠️

阅读器 HTML 里有 `var scramble_id = 220980;` —— 按那个站的设计，**编号大于它的作品**，图会被 JS 打乱再还原。

- 实测那个例子（1481228）**大于**它，但**下到的图看着是干净的**
- **这一条没有验透** —— 现在只在日志里记一句 warn，不拦

**如果你遇到"图是花的/错位的"，那就是这个。**

## 5. 面板里 **`jmRead` 在顶层**，别按 `qq.jmRead` 找

## 6. 花费估算按 `$0.0074/次` 算，**是估算**

实际单价会随渠道变。面板那一行只是给个量级。

## 7. 梗库是**快照**

6668 条，2026-10-26 建的，**不会自动更新**。没命中的会自动走联网搜索兜底。

# 七、修了：**接梗被拿去联网**（用户现场抓到的）

## 现场

```
你在私聊里发了一张表情包，配字「真好吃吗」。
日志：
  bridge：「[表情包] 真好吃吗」 图×1 决策 → 发言
  bridge：**需要联网（在问某个东西好不好）→ 查「真好吃吗」**   ✗ 搜了
  bridge：搜索用量已记录（in=899 out=89，**搜了 1 次**）        ✗ 花了钱
```

**三重代价**：慢 **1.85 秒** ✗ / 一天 **12 次**的预算占掉 **1 次** ✗ / 搜回来的 148 字**毫无用处** ✗
—— 那是**接表情包的梗** ✓，不是求知 ✗。

## 根因：两处都不匹配，于是漏进了"短线问句"那层

判据里本来**专门**排除这种句子（`好吃吗` 就在名单里 ✓），但实际收到的是
「**[表情包] 真**好吃吗」—— 两个字都不对：

1. 前面挂着**段标记** `[表情包]` → 而那条正则是 `^…$` **锚定整句**的 → 直接失效 ✗
2. 是「**真**好吃吗」，名单里**没有程度副词**这个形态 ✗

⚠️ **这个坑代码注释里早写着**（`search.js` 的 `bareAsk` 那段：
「`bareAsk` 盖不着，于是被判成『在问某个东西好不好』搜了一次」）——
今天只是**换了个触发词**又撞一次 ✓。

## 三处改动（都在判据函数里，不动消息处理那边）

| # | 改动 | 作用 |
|---|---|---|
| ① | 识别段标记（`[表情包]` / `[图片]` / `[表情:N]` …），**带图的消息不走任何隐式搜索** | **最治本** —— 从来源断，不靠正则去猜"这句算不算问题" |
| ② | 判据一律跑在**剥掉段标记之后**的文本上 | 锚定正则恢复有效 |
| ③ | 加**程度副词**前缀（真/挺/好/蛮/超/太/很/特别/贼/怪） | 「真好吃吗」「挺好看吗」不再漏 |

★ **① 是加在两条隐式路径共用的总判据上的** —— 所以一次挡住全部隐式搜索 ✓；
而「**用户明确要求搜**」在那之前就返回了 ✓ ——
**「[图片] 搜一下这是什么」照旧会搜** ✓（实测过 ✓）。

## 验证（15 条对照）

```
✓ [表情包] 真好吃吗        → 不搜   ← 现场那句
✓ 真好吃吗 / 挺好看吗 / 好厉害吗 → 不搜
✓ [图片] 这谁啊 / [表情包] 你吃了吗 / [表情:12] 好玩吗 → 不搜
✓ 搜一下 RTX5090 的参数 / 帮我查查今天的天气 → **照旧搜**（没误杀）
✓ [图片] 搜一下这是什么    → **该搜**（带图 + 明确要求 → 放行）
```
全量 **91/91** ✓。
