# 一、协议端：NapCat → **SnowCat**

## 为什么换

NapCat 上游仓库（`NapNeko/NapCatQQ`）已于 **2026-11-12 被清空**：只剩一句「到这里告一段落」，**Release 与 Tag 全部删除**，文档站也 404。自动下载那条路彻底断了。

现在接的是 **SnowCat**（<https://github.com/DandanLLab/SnowCatQQ>）：跑在**官方 QQ 9.9.37 主进程内**（`winmm-v8.dll` 侧加载 + V8 注入），比外挂注入更抗风控。

## 适配了什么

| 能力 | 说明 |
|---|---|
| **启停** | 发现 SnowCat 便携目录就走 `tools/build/snowcat-run.ps1`（`-Stop` 也走它）；不再是我们 spawn 的那个 powershell 子进程 |
| **控制面板** | `webInfo` 改读 SnowCat 的 `config/webui.json` —— 面板按钮**自动带 token 登录**，不用你手抄 |
| **进程列表** | SnowCat 的 QQ 进程在独立目录，`listProcesses` 单独认它 |
| **状态** | `running` → `connected`（更贴近真实：进程活着 ≠ 连上了） |

⚠️ **SnowCat 的 packetBackend 不能发包**（会直接报错）—— 所以「戳一戳」从「戳回去」改成**永远走说话**：能感知被戳、正常接话，但不再回戳。

# 二、生图 / 自拍：photo-v3 全套

## 三个规划器 + 一个唯一出口

```
intent（她要什么）
  → camera-planner（7 种模式几何 + 5 种 POV 子型）
  → framing-planner（取景不动机位，上物下手的布局）
  → pose-planner（肢体唯一真源、三类手去重、接触关系、动作/可见分离）
  → visibility-resolver（**可见性唯一出口**：手数量 ≠ 可见、镜拍裁决）
  → buildShotPlan（四层静态合并）
```

以前的病是**同一件事在四个地方各写一遍**，彼此打架（手数、镜子、谁入画）。现在可见性只有一个出口。

## 手部专项

- **`handContract`**：按模式给契约（对镜 / 第一人称 / 后置自拍 / 脸特写…），Prompt 里只写**唯一一行**契约
- **审核**：`reviewHands` 结构审核（左右、结构、边缘复核），`mirror` 手数上限 **2**，`face_closeup` 也纳入契约（**最多 1 只，持机手不入画**）
- **发送前门禁**：复审仍违规 → **不缓存、不发送**
- 失败处理：审核 **3 次重试（400ms 间隔）+ 45s 超时**；视觉服务不可用时默认**放行**（`failClosed` 可配）

## 画面

- 瞳孔硬编码为 **photo-v3 蓝眼**（「清澈的宝蓝，不要灰/棕/黑」），带参考图的分支也硬写 —— 修掉了「全景里蓝眼被小参考图压成棕眼」
- **耳鳍**：小小贴耳薄片，不超过耳朵大小，禁止大翅膀 / 鱼鳍披风
- 部位词换成**服装 / 构图术语**（内部 ID 不变）—— 不再跟上游 400 硬碰硬
- 部位特写改用**局部参考图**（参考图就是构图基准）
- 自拍姿势池 + 小红书提炼的「生活照自然感」规则

## 参考图管理

`reference-manager` 四策略（canon / 脸 / 兜底 / none），costume 参考图**拒用**，A/B 版本隔离；canon 比较改成 `outfitId` / `outfitText`（match 只做命中）。

## 衣柜

- **41 套（家居 / 外出 / 睡眠）**，换装必须对得上衣柜原文
- **可编辑**：数据目录 `wardrobe.json` 覆盖预设，**mtime 热加载**
- 侧栏衣柜面板（在「生成图」上面），摘要进对话提示词（她知道自己的衣服）

## 拍之前

「拍什么、怎么拍」先问清楚；「还想要 / 再来一张」归为**软请求**，不直接开画；记住「刚承诺过要拍」——用户回「嗯 / 好 / 要」就直接画。

# 三、QQ 空间「说说」

- **独立调度器**：只出草稿，**私聊确认后才发**（`[说说]` 标记）
- **群里一律不准发说说**；私聊无冷却
- **配图**：按「她自己说过的话」生成 / 回找主体词；只带**能公开发**的图（私房照 / 家居服对镜**不进空间**）；暂停过一阵「动漫脸参考图」的配图
- **限频**：20 小时
- 发完**写进她的记忆**；说说正文不能是回复语；缺图会回看最近 8 条消息里的图

# 四、对话质感

## 分段与插话

**麦麦式分段**：一条回复拆成多个气泡发，不再一整坨。**插话打断**：她说到一半用户可以打断，新消息优先。

## 其它

- 戳一戳：走说话（见第一节）
- 表情包：看懂意思就行，**不描述、不评价画面**；不认领「这图是不是我」
- 群里没头没尾：最多回一个「？」/ 表情，之后最多再问一次
- 话题叫停：「别老提这个」→ 她放手

# 六、图片链路

- **参考图取本地文件、multipart 直传**（不再 base64 内联）—— 修掉上游 **400**
- 生图网关走**强制直连**的原生 http/https fetch（本机 `127.0.0.1:3425`，**不读 HTTP_PROXY** —— 代理软件没开时不再 502）
- 审核缩放提到入口处，旧审核与重拍复审共用同一份 640 图；缩图失败按放行处理并保留原图
- 图片缓存（3 天）、去重、合并转发、`[删说说]`

# ★ 注意事项

## 1. **协议端要自己装 SnowCat**（这一版最大的前置）

NapCat 上游已被清空，**自动下载没了**。你需要：

1. 装一份 SnowCat（<https://github.com/DandanLLab/SnowCatQQ>）
2. 默认放在 `D:\SnowCat.Portable`；装在别处就设环境变量 `SNOWCAT_ROOT` 指到目录
3. 目录里要有 `tools/build/snowcat-run.ps1`（启动/停止都走它）

放好后 WhalePod 会认出它、显示「已连接」，控制面板也能自动带 token 打开。

## 2. **戳一戳不再回戳**

SnowCat 的 packetBackend 不能发包。她仍然能感知被戳，也仍然会接话 —— 只是不会「戳回去」。

## 3. 生图依赖本机 MCP 网关

默认 `http://127.0.0.1:3425/mcp/magpie/tools/minimax`。网关没起 = 画不出来（日志里会说清楚，不会静默）。

## 4. 审核不可用时**默认放行**

视觉服务挂了 / 没配 key 时，为了不静默丢图，默认放行；想要更严格可打开 `failClosed`。代价是「审核没跑」的图也可能发出去。

## 5. **说说必须先确认**

她只出草稿，**私聊里你点头才发**；群里永远不会自动发。20 小时限频。

## 6. 数据目录多了些文件

`wardrobe.json`（衣柜，可手改，mtime 热加载）、`diary` / `home` / `wearing` 等。老数据目录可以直接用，首次会补默认。

## 7. 仍然是 beta

3 周换了这么多东西，beta 标签没摘。

# 升级提示

- **0.4.x → 0.5.0 有一件不兼容的事**：协议端没有 NapCat 就起不来了，必须先装好 SnowCat（见注意事项 1）
- 配置**新增键自动补默认值**，老 `config.json` 不用手改
- 装成 DSH 插件后**要重启 DSH**（客户端插件有缓存）；只重启鲸舱不够
- 面板里的旧「组件 → 一键装 NapCat」按钮已经不可用，别再点它
- 全量测试：**180 / 200** —— 并发回复 / 主动发言闸门 / 发送漏斗剥标记这三处已修好并通过；余下 18 个多为提示词措辞、交互门限类断言，仍在跟进
