# 审查包：V3 摄影系统 · 12 张真实生图对照

> 分支：`review/photo-v3-shadow-images`（独立分支，仅实验产物，不含任何正式链路改动）
> 用途：请 GPT 审查「V3 规划链 vs 旧链路」在同一批输入下的真实出图差异。

## 一、这次实验在验证什么

不是"哪张更好看"，而是：

1. V3 是否**减少**了旧链路那些不自然的拍照行为（第三人称冒充第一人称、多手、持机手入画、物品照里出现人、背影露脸等）；
2. 差异是否**能归因于规划器**，而不是 Prompt 质量或随机性。

## 二、公平性控制（关键）

| 项目 | 设置 |
|---|---|
| 生图模型 / 采样参数 / 画幅 / 分辨率 | 两侧**完全相同** |
| 角色参考图（是否给、给哪张） | 由**各自的规划结果**导出：旧=`plan.faceVisible`，V3=`visibility.face` |
| 公共角色设定 / 场景原句 / Prompt 骨架 | **完全相同**（同一份 `shadow-v3-prompt-adapter.js`） |
| 唯一变量 | 机位 / 取景 / 手部 / 可见性等**规划字段的值** |
| 随机种子 | provider **不支持固定 seed** → 单张差异含随机性，请按"结构性错误"判断，不做像素级比较 |

## 四、请按五项逐场景评估

| 场景 | 验收点 |
|---|---|
| 1 前置自拍 | 自然表情、合理自拍距离、不出现摄影师 |
| 2 对镜自拍 | 手机与持机手关系正确、镜中比例合理 |
| 3 第一人称端杯 | 动作手正确、杯子接触关系自然 |
| 4 桌面写字 | 笔/纸/手关系合理、不多长手 |
| 5 后置拍物 | 物品是主体、不出现无意义持机手 |
| 6 背影 | 背部朝向正确、不意外露脸 |

每个场景看五项：①机位与视角 ②肢体数量与动作合理性 ③人物与物体接触关系 ④取景与构图 ⑤角色表现与真实摄影感

**贯穿检查**：鲸鱼尾巴只能作为挂件/装饰，不得生成身体尾巴。

## 五、已发现的关键问题（请重点复核这条）

第一轮实验里，两侧都传了人脸参考图，结果**两张都是第三人称怼脸自拍**——连 V3 也被拉回去了。

修正为「`visibility.face=false` 时不给人脸参考图」后，V3 的第一人称端杯变成真正的俯视 POV。

**结论**：只在规划里写"脸部不可见"不够，**参考图策略必须作为规划输出的一部分并被执行**。请复核这个结论是否成立，以及是否还有其他类似的"规划正确但生成侧不执行"的落差。

## 六、已知局限

- 无固定 seed，单张差异含随机性。
- 适配器刻意最小化：只翻译字段，不补充规划器没输出的内容（因此"手怎么握杯柄"这类细节不会出现在 Prompt 里）。
- 这是证据收集，不是接入验收；未修改 `index.js` / `bridge` / `photo-prompt.js`。
