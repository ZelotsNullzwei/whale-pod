## 三、根因判断

**「群聊中随机插话」这条兜底规则，对表情包消息不该生效。**

推断的调用链：

1. 表情包消息进来，`「[表情包]」图×1` —— **没有文本内容**
2. 五条判据（引用谁 / 叫了谁 / 接着上一句 / 承接词 / 隔了多久）**全部拿不到证据**
3. 判据链没有命中「明确不该回」，于是落到兜底
4. 兜底走了「群聊中随机插话」，按 p=0.90 / p=0.65 掷骰子
5. 命中就发言

**这和 v0.2.5 的设计意图相反** —— 设计上应该是「证据不够就不猜」（视频里 n7 那一屏讲的就是这个），实际却是「证据不够就掷骰子」。

### 重点怀疑方向（按可能性排序）

**① 兜底规则没有排除「无文本消息」**（最可能）

「随机插话」本意应该是「群聊很热闹、有文本内容、机器人可以凑一句」，但代码没检查消息是否有文本，表情包也走进了这条路。

**② 表情包被当成「有内容」**

`「[表情包]」图×1` 这个描述说明消息被归一化成了字符串，可能因此通过了「是否有内容」的前置检查。

**③ 判据链在无文本时直接短路到兜底**

五条判据都依赖文本，无文本时可能整体返回「无法判断」，而「无法判断」被当成「可以随机试试」而不是「不接」。

**④ 冷却补回机制放大了问题**

日志里有 `冷却中，16s 后补回「[表情包]」` —— 说明表情包消息还会被**排队补回**。冷却结束后会再判一次，如果那时又命中随机插话，等于同一个表情包触发两次。

## 五、修复要求（不能只修一半）

### 必须满足

1. **连发 5 个不同表情包，机器人回复数 = 0**
2. **发「@机器人 + 表情包」，机器人正常回复** —— 不能矫枉过正，把 @ 场景也挡掉
3. **跑 `check-decision.mjs` 与 `check-social.mjs` 全绿**
4. **v0.2.5 已有的五条判据用例不能退化**

### 不允许的修复方式

| 禁止 | 原因 |
|---|---|
| 屏蔽所有图片消息 | 用户 @ 机器人时发表情包应该正常回 |
| 调高随机插话阈值 | 掩盖判据链本身的缺陷，换一批消息还会犯 |
| 只加冷却时间 | 治标，39% 的命中率降到 20% 还是每五个表情包回一次 |

### 建议的修复方向

**在「随机插话」规则入口加一道前置检查**：

```
如果消息没有文本内容（只有图片/表情/文件等非文本 segment）
  → 不走随机插话，直接沉默
  → 除非明确 @ 了机器人
```

这样既修掉表情包乱插话，又保留「@ + 表情包」的正常回应。

### 关键结论一：模型**确实有视觉能力**

机器人对每张图的描述**准确对应图片内容**：

| 图片 | 机器人回复 | 是否看懂 |
|---|---|---|
| 青蛙 | 「这青蛙肚子比我还圆」 | ✅ 认出了青蛙和圆肚子 |
| 鲸鱼娘哭脸 | 「谁把本鱼画成流口水发呆的样子啊」 | ✅ 认出了是自己、认出了流口水发呆 |
| 猫趴桌睡觉 | 「这睡相也太真实了」 | ✅ 认出了睡姿 |

**所以「若模型不支持视觉，图等于没传」这个假设是错的** —— 图片确实传进去了，模型确实看到了。
（日志里那句话只是防御性提示，不是当前实际情况。）

### 关键结论二：问题比「随机插话」更深

真实链路是**两步**：

```
第 1 步（规则层）：表情包消息 → 无文本 → 落到「群聊中随机插话」→ p=0.90 命中 → 决定「发言」
第 2 步（模型层）：既然决定了发言，就把图片喂给有视觉能力的模型 → 模型看懂图 → 生成很贴切的吐槽
```

**这就是为什么回复质量很高、很贴合、很有角色感** —— 不是模型乱说，是模型太会说了。

**问题纯粹在第一步：它根本不该被允许发言。**

这也解释了为什么只调阈值没用：只要放行一次，模型就会给出一次高质量回复，观众感知就是「它又在接表情包」。

### 关键结论三：连续发言控制不够快

第 5、6 条是机器人**连续两条**消息（「谁把本鱼画成…」+「……嗯，也可能有点像。」）。
第 8、9 条是机器人**先发表情再发文字**，也是连续两条。

日志里「已连续发言 3 轮，主动收尾」出现了 87 次，说明轮次控制存在，但**允许它连发 2-3 条**。
对表情包场景来说，连发两条就已经很打扰了。

### 关键结论四：机器人还会主动发表情

第 8 条是机器人**主动发了一个表情**（不是文字）。
这可能是独立功能（表情互动），但和「不该接表情包」叠加后，观感更吵。

### 修复要求补充（在原要求之上）

6. **表情包消息不该进入模型层** —— 在规则层就拦掉，不要「先决定发言再把图喂给模型」
7. **连发控制对表情包要更严** —— 表情包场景下不该出现连续两条
8. **「主动发表情」也要受同一道门控** —— 否则文字拦住了、表情还在发
9. **不要破坏模型的多模态能力** —— 模型看图能力是好的，@ 机器人发图时应该正常用
