## 她终于能"听懂"B 站视频了

以前群里分享 B 站链接，她看到的是：

```
【显卡驱动更新完三角洲行动很卡怎么办】https://www.bilibili.com/video/BV...
```

**只有标题。** 标题党的话，接的话基本等于瞎猜。

现在她看到的是标题 + UP + 时长 + 简介 + **评论** + **弹幕** + **视频里说了什么**。

### 三样信息各有分工

| 来源 | 是什么 | 回答什么 |
|---|---|---|
| **音频转写** | 视频**本身** | 讲了什么 |
| **弹幕** | **当场反应** | 哪个瞬间炸了、哪句被反复刷 = 梗 |
| **评论** | **事后评价** | 值不值、大家在吐槽什么 |

三样是**互补**的，不是三份材料各念一句 —— 真人看完一个视频，说的是
"讲了什么 + 哪里好玩 + 值不值"的**混合体**。

### 为什么"评论和弹幕才是重点"

有用户说得很准：**「光是标题和简介只是作者说明，评论和弹幕才是重点」**。

标题简介是作者自述，评论才是观众怎么看。

**弹幕按「出现次数」取，不按时间** —— 弹幕的价值在**重复**。
实测一条 MV：`×34 你被骗了`、`×8 年年考，年年错`。
按时间取前 20 条只会拿到开头几秒的零星反应，取不到"这个视频的梗"。
（只出现 1 次的不列 —— 那不叫梗，列出来反而乱。）

### "听懂"是怎么做到的

三条路里前两条都断了：

```
x/player/v2 的 subtitle.subtitles    匿名恒 0 条（CC 字幕要登录）
x/web-interface/view/conclusion      -403 权限不足
```

**但音频流是免登录的**（`x/player/playurl` 返回 DASH 清单）。
所以：**下载音频 → 本地 whisper 转写 → 等于"听懂"了**。

41 秒的视频，转写约 4 秒，一条链接端到端约 4 秒。
一句话的误差是有的（`DeepSeek Harness` 会被转成 `DipSikHanis`），
但**大意完全对得上** —— 所以在提示词里明写了"这是机器听写，别当精确引文"。

**音频用完立刻删，转写文本只在内存缓存（LRU 50 条），不落盘。**

### 踩过的坑（都给注释了）

1. pip 装 `faster-whisper` 卡了 15 分钟 → 换清华源，60 秒装完
2. 下模型 401 → 新版 `huggingface-hub` 走 `hf-xet` 的 CAS 服务器，镜像不认 → `HF_HUB_DISABLE_XET=1`
3. `TypeError: open() got an unexpected keyword argument 'metadata_errors'` → `av 19` 删了这个参数 → 降级 `av 13.1.0`
4. 转写输出全是乱码 → Windows 的 Python 默认 GBK，而 Node 按 UTF-8 读 → `sys.stdout.reconfigure(encoding='utf-8')`
5. 想让 whisper 直接出简体的 `initial_prompt` **反而更差**（「DeepSeek Harness」→「Deep Secret Honest」）→ 去掉 prompt 保准确，改用 OpenCC 事后转简
6. 主 CDN `mcdn.bilivideo.cn:8082` 本机 **DNS 解析不了** → 必须把 `baseUrl` + 所有 `backupUrl` 平铺成列表按顺序试

## 收藏表情现在有标签了

48 张收藏表情自动打标签（`震惊、崩溃、抓狂、难以置信` / `无语、嫌弃、冷漠、看戏` …），
**她知道自己的表情是什么意思**了 —— 需要时可以按意思挑（`[表情包:震惊]`）。

顺带修了一个隐蔽的 bug：给表情打标签走的是视觉模型，
而推理模型的 `reasoning-delta` **也带 `.text`** —— 一开始收进来的是它的草稿
（前 5 张的标签是「分析用户请求：」「可能是动画的一帧」这种）。现在跳过草稿。

## 「不像真人」这次从三个方向治

**① 人机感是三样凑出来的**（参考 `dsh-bili-scroll` 的章程）
```
开头「关于这件事……」/「这个视频……」   ← 八股开头
中间「首先 / 其次 / 最后」或分点罗列     ← 作文
结尾「如需更多信息请告诉我」             ← 客服尾巴
```
好的回复 = **一句人话判断 + 一个只有当时在场才说得出的细节**。

**② 你不是助手，是聊天对象**

实测它会在被调试时变成"技术助理"，回「还是不行」「没展开」「这条我手上什么都没有」——
那是念工作日志，不是聊天。现在明写了边界。

**③ 把它自己刚才说过的话喂回去**

参考实现的注释说得很准：没有这段，它每轮都从零开始，自然每条都往"平均腔调"上靠。
现在每次生成会带上它最近 3 条回复，并明确要求「别用相同的开头、别套同一个句式」。

## 事实通道：一个架构改动

实测事故：B 站信息**确实进了 prompt**（8411 字里第 3600 字），
但模型回「又是链接，本鱼这边还是没展开」—— **连标题都没用**。

根因是模型分不清两类文字：
```
① 程序抓到的真实数据      ← 真的
② 它自己上一轮说过的话    ← 可能错
```
两者在上下文里长得一样，而②更近、更像"我的经历" → 它信了②。

所以给①一个**独立通道**：单独成段、带权威标记、放最末尾、
并明确写「和你之前说过的话冲突时，以这里为准」。

## 其它修复

- **群聊不爱回**：决策层有条「己方无法提供有价值的回应 → stop」，几乎一律闭嘴；
  另外 `wait` 和 `stop` 的概率都是 0，**行为上完全没区别**（`wait` 现在给 0.3）
- **联网搜索抢戏**：拿 `b23.tv` 短链去搜「专有名词」，搜不到还把 B 站真信息盖掉了
- **分享卡片被丢弃**：`json`/`xml` 段原来「其它类型：忽略」→ **整条消息消失**，
  她以为是"手滑发了条空的"。现在能抠出「【标题】链接」
- **`（+几秒）` 注解泄漏**：我加给历史的时间标注被当台词念了出来
- **`（笑）` 被整条吃掉**：第 ⑫ 条规则「整条只有一个括号 → 丢掉」把正常台词也吃了
- **4 张图只看到 2 张**：`config.json` 里 `maxImages: 2`（旧值）——
  DEFAULTS 只填**缺失**的键，不会覆盖已有的旧值
